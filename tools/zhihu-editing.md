# 知乎文章的编辑与修复流程

本仓库的文章先经 `zhihuify.py` 转换, 再导入知乎发布 (文章页脚显示"本文使用 WPL/s 发布"). 2026-11-01 第一次用知乎网页编辑器修改已发布文章 (0.0 篇的葛立恒数) 时, 发现编辑器本身有两个会破坏文章的 bug. 本文记录 bug、规避流程, 以及修复已发布文章时子智能体与最终审查各自要做的事.

## 已知 bug (2026-11-01, 知乎网页编辑器)

| 编号 | 现象 | 原因 (推断) | 影响范围 |
|---|---|---|---|
| Z1 | 多行公式 (`$$\begin{aligned} … \end{aligned}$$` 等) 的 LaTeX 里出现字面 `<br>`, 发布后渲染成 "< b r >" | 导入时公式内部的换行被转成 `<br>`; 旧版渲染忽略它, 编辑器重新保存后变成可见文本 | 所有经 Markdown 导入、含多行公式的文章; 只要在编辑器里保存一次就会暴露 |
| Z2 | 文章开头的引用块 (交流Q群 / 本文源码 / 高亮渲染 三行) 被拆成三个段落并插入空行 | 引用块内的软换行 (行尾两个空格) 被编辑器改写成段落 | 所有文章的开头 |
| Z3 | 用工具栏 ∑ 插入行内公式后, 公式旁多出一个空格 (如 "ψ(Ω_ω) ." / "( i<j )") | 编辑器插入公式对象时自动补空格 | 所有新插入的行内公式; 已有公式不受影响 |

这两个 bug 都在编辑器打开并保存文章时触发, 与改了什么内容无关.

## 规避 (源头)

`zhihuify.py` 已加第 0 步: 把每个跨行的 `$$ … $$` 块合并成一行, 公式内部不再有换行, Z1 不会发生. 今后发布新文章或整篇重发时用新脚本. Z2 没有源头规避: 只要用编辑器保存, 开头的引用块就要按下面的流程修一次.

## 修复已发布文章的流程 (子智能体执行)

0. **留底**. 用 `get_page_text` 抓发布页全文存下来, 以便事后 diff.
1. **做预定的修改**. 代码块直接改文本; 公式双击打开"公式编辑器", 全选后重打 LaTeX, 看右侧预览, 再点"确认"; 正文文字用点击定位加 Shift+方向键选中后输入替换.
2. **清扫 Z1**. 在编辑页上 `get_page_text`, 它会打印每个公式的 LaTeX; 列出所有含 `<br>` 的公式, 逐个打开公式编辑器, 用源文件 (`src/*.lagda.md`) 里对应 `$$` 块的 LaTeX 重打, 行与行之间用空格连接 (`\\` 已在源里). 单行公式不要动.
3. **修 Z2**. 把开头三行合回一个引用块, 行间用 Shift+Enter 软换行, 保留原有链接, 删掉多余空段落.
4. **全文目检**. 截图滚一遍, 确认没有 "< b r >"、没有多余空行、改动处正确.
5. **发布**. 先"预览", 再点"更新". 发布是不可逆动作, 必须有作者的明确授权 (针对该篇).
6. **发布后核验**. 打开发布页 `get_page_text`, 检查公式文本里没有 `<br>`, 开头没有空行; 与第 0 步的留底 diff, 确认只有预定改动.
7. **汇报**. 列出改过的公式 (章节 + LaTeX 首行)、开头块的处理方式、是否点了更新、核验结果、截图路径、未解决项.

## 最终审查 (主会话执行)

- 对每篇修过的文章: 自己再 `get_page_text` 发布页一次, grep `<br>`; 比对源文件 (`src/*.lagda.md`) 的对应段落, 逐项确认预定改动已落地且没有误伤; 看截图.
- 对 src 的改动: 重新编译涉及的模块 (用 `--library-file` 指向正确的库列表), 并检查 `git diff` 只包含预定改动.
- 记录: 本文件的 bug 表与 `probes/README.md`/记忆同步更新.

## 清扫 Z3

每插入一个行内公式, 立刻用方向键定位到公式两侧, 删掉多余空格后再目检; 若公式与标点相邻 (如 "$x$." / "($i<j$)"), 发布页上检查 "x ." "( i" 之类的间隙. 此项与 Z1/Z2 一样在"目检"步骤复查一遍.
