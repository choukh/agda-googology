## 1 两路回报的复核

### 1.1 YiWall (障碍审计)

四件 (`YiWallLim`, `YiWallTree`, `YiWallConditional`, `YiWall`) 主审此前已从盘上冷编复核, 记在 LOG. 作者转来的报告与复核一致.

- **定理:** 片段接口里, 极限行加有界位置保持就推出 "同一棵树换证书后整个输出函数相等" (`YiWallLim.Required.sequence`); 这个最小接口有闭实例 (`cut-instance`), 所以它本身不推出一般的函数外延.
- **条件定理:** Funext 加一个只读树且满足片段接口的 ψ, 推出 WLPO (`funext-fold-tree→wlpo`). 证明用的探针是下界不合法、守卫域为空的结点 (`EmptyAgreement` 的前提就是 `Lgl 0 c → ⊥`).
- **未证:** 不带 Funext 时的蕴涵.
- **主审的读法 (判断, 元层):** 类型论加 Funext 是相容的, 且不证明 WLPO; 所以在不加公理的 Agda 里, 写不出同时满足条件定理全部前提的 ψ. 也就是说, "旧块上, 只读树, 对全部合法结点满足片段接口" 这一种形状走不通. 它不涉及读证书的 ψ, 也不涉及结点类型里没有空守卫域的块.

### 1.2 YiIntr (证据进树的侦察)

六件主审本次冷编: 6G, 退出码全 0, 各有 `Checking` 行; `--safe --without-K`; 禁用构造 0; 无本机路径; `importclosure` 通过. 读过陈述.

| 档 | 结果 | 范围 |
|---|---|---|
| 编译事实 | 结点内置下界合法 `w`, 嵌套下界 `b`, 根位置路径 `p` 的归纳—递归块通过正性与停机检查 (`YiIntrCore`) | 独立的平行类型 |
| 编译定理 | 起点只读结点字段: `start-node (lc k c w b t p g) = g c (refl , w , b)`, 对一切层号 (`start-lc`) | 只有起点, 不是 gt 行 |
| 编译定理 | 一切新树自带新类型上的 `Reg` 与 `Carry⁺` (`all-Reg`, `all-Carry⁺`) | 新类型上的同形谓词, 不能送回旧接口 |
| 编译构造 | `tw₀` 到 `tw₃`; Ω 带环境前提 `Ready`, 不是 `LF → LF` | 有限四项, 没有全塔与 Λ |
| 编译否定 | `no-total-ready`: 这套环境合同不能对一切新树给出 | 只否定这套合同 |
| 编译否定 | `tw₃-not-root-irr`: `tw₃` 的同一坐标有两份守卫证明, 分支给出两棵不同的树 | 只否定这种内置写法 |
| 估计 | 迁移范围约 25 件, 4204 行 (现有文件的复制范围), 一致性问题未解决时没有上界 | 估计, 不是定理 |

**失败的机制 (读代码得到).** 内置的路径 `p : Reach (suc k) t` 是带证明内容的数据: 它经过 Ω₁ 的某个分支, 路径里含那一支的守卫证明; 守卫证明里的 `Cp` 在极限处要选一个下标. 同一坐标 `suc (lim (const 1))` 选第 0 项与第 1 项是两份不同的证明, 于是两条路径不同, 两棵树不同. Ω 需要 `Ready` 环境, 也只是为了生产这条路径.

**这与复盘的预测一致.** 复盘 §5.1 写过: 证据进树之后 "树的字面相等会牵涉证明项的相等, `Un` 一类问题可能回来". 回来的正是这一件.

### 1.3 两路合起来说明什么

旧块上的两种 ψ 都卡在同一处: 证明被当成了数据.

- 读证书的 ψ: 证书是普通参数, 输出里留下证书的痕迹, 一致性要到函数相等 (`lim-function-equality-required`).
- 只读树的 ψ: 调用不了分支 (起点的守卫要 `Lgl k c`, 树里没有); 在全合法域上还会碰到空守卫域的结点.
- 证据作普通参数进树 (YiIntr): 证明成了树的数据, `irr` 失败.

三处要的是同一件东西: **树里有证明, 而证明不参与树的相等.** 这正是无关参数的语义. 外部模型的两份报告都如实写了范围 ("不否定所有内置方案", "尚不能据此关闭只读树路线"); 风险在读的一方把 "不采用" 当成方向已否定.

## 2 最小实验: 证据作无关参数

文件: [RR5IrrCore](../OCF/Align/RR5IrrCore.lagda.md) (块的定义, 164 行), [RR5IrrCheck](../OCF/Align/RR5IrrCheck.lagda.md) (读回, Ω, 核对, 153 行). 冷编 6G, 退出码 0; `--safe --without-K --lossy-unification`; 禁用构造 0; 无 Funext; 导入闭包只有这两个模块与标准库.

**改了什么.** 逐行平行 `YiIntrCore`, 只改三处: `w`, `b` 标为无关参数; 分支函数的守卫参数标为无关 (`g : (η : Raw k) → .(Gd k c η) → LF`, Raw 的 `lc` 同样); 不内置根位置路径, 位置证据仍像原块那样在树外. 无关参数是 Agda 的语言特性, 不要额外选项, 标准库在同样的选项下也用; 它不给出 `Set` 里相等证明的唯一性, 与 K 无关. 仓库此前的定义里没有用过它 (检索到的 `.(…)` 都是点模式).

| 档 | 结果 |
|---|---|
| 编译事实 | 带无关证据的归纳—递归块通过正性与停机检查 |
| 编译定理 | `evidence-irrelevant`: 换掉结点里的两份证明, 树不变 (`refl`) |
| 编译定理 | `all-root-irr`: 原 `Legal.irr` 的同形陈述对一切树成立 (`refl`); `raw-irr`: Raw 一侧同理 |
| 编译定理 | `actual-same`: YiIntr 反例坐标的两份守卫给出同一棵树 |
| 编译构造 | `Ω̂ : LF → LF` 没有前提; `tw : ℕ → LF`; `Λ` |
| 编译定理 | `tw₂-start`, `tw₃-start`, `tw₃-next`: 只读树的起点与下界加一的那一支, 对一切层号有定义, 在塔上算出预期的树 (`refl`) |
| 编译定理 | `CertIrr.lim-function-coherence`: 证书参数无关时, 换证书后的两个极限函数定义性相等 |
| 编译定理 | `all-guard-nonempty`: 没有守卫域为空的结点 (双重否定形式) |

**它回答了什么.**

- YiIntr 的 `irr` 失败与 "Ω 要环境" 两条, 在无关写法下都不出现.
- 复盘 §3.3 的两难 (读证书则输出依赖证书, 只读树则调用不了分支) 在类型一级解开: 证明可以存在树里或作无关的证书参数, 交给分支时不成为输出的数据.
- YiWall 条件定理的探针 (空守卫域的结点) 在这个类型里不存在.

**它没有回答什么.**

- 没有新块上的 `Legal` 闭包, 没有折叠, 没有值, 没有与旧块的对应. `CertIrr` 的两条对任何类型都成立, 它们的意义只在 "这样的算子在新块上调用得了分支" (`call`, `start-node`), 而完整的算子没有写.
- **判断, 未验证:** 折叠是否处处只在无关位置用这些证明. 支持的依据: 原块的规范构造 (`up`, `Ω̂`, `cO`) 本来就不看守卫, `Legal.irr` 在那里是 `refl` 传下来的.
- **判断, 未验证:** 目标层不为 0 时, 三路派发要拿位置证据当数据分情况, 那一处无关参数帮不上, 仍要靠公共界下的判定型证据. 第一次回灌才会碰到.
- `Kid` 里仍有相关的守卫证明 (`em` 坐标的两个孩子按 `(η , e)` 区分), 本次没有改. 旧块的 `Un` 问题出在这里; 用带无关分量的记录也许能一并消掉 (判断).
- 规则层面: 无关参数能否进成品候选, AGENTS 没有写, 要作者定 (§6).

- **停下的理由是 "不需要" 而不是 "做不到" 的:** D7 四轮 (严格化在规范塔上不需要, `RR4RegOmega2.Ω₂-reg`).
- **作者的投入决定, 并已明写 "不是否定":** RouteSeal 各族; 2026-11-03 经 Fable 5.1 审核的七个方向 (RESULTS 的 "历史投入决策" 表).

## 4 执行质量的评估 (判断, 依据见各条)

**子智能体 (11-04 至 11-07).**

- 纪律是好的: 否定都有可满足的前提, 范围写明, 措辞合规. StallDiagnosis 已核过.
- 弱点是 "换接口不换共同假设" 与 "停在第一个障碍": 同一条引理的局部形状被十几路各碰一次, 没有一路去定它. 这在 StallDiagnosis §4 与第三次审查 §1.2 已两次指出, 之后的 B 簇仍然如此.
- 值一线尤其弱: A, B 两簇 34 个文件, 没有一条越过 Ω+1 的上界, 也没有一条一般的单调引理或它的反例.

**外部模型 (11-08 至 11-10).**

- 强项: 每轮都能编译, 不夸大, 范围写得准; 接口的否定与规范实例上的归纳做得好 (`no-K2′`, `k1′`, `tower-carry⁺`).
- 弱项一: 主构造需要改设计时交不出. 目标层 0 的完整递归 ψ 三轮没有交, 每轮换成具体的族加一份障碍分析.
- 弱项二: 不试别的编码. 证书一致性的障碍与 YiIntr 的 `irr` 失败是同一个根, 两轮里都没有试 "让证明不参与相等" 的写法; YiIntr 反而把带证明内容的路径内置进去, 失败由此而来.
- 弱项三: 侦察的产出偏向账目 (迁移范围表, 切片表), 决定性的小实验做得少.

**主审 (本会话) 自己的部分.**

- K2′ 连续三轮接受了 "部分交付", 每次的回应是再补接口字段, 没有回头问表示方式.
- 复盘时已预测 `Un` 会回来, 但给 YiIntr 的简报只要 "正性, 依赖, 成本", 没有要求在失败时试替代的写法. 软结果有一半是简报问出来的.
- 第四次审查提出 K3, K4 之后, 主审把全部派发都放在 K1, K2 一线, 这两项便宜的判定题没有派.

**结论 (判断).** 两类执行方的共同短板是设计层的判断: 在一个表述失败时, 换表述, 或把共同的那条陈述单独拿出来定. 这正是三次先例里独立审查补上的东西. 所以换更强的模型重开, 对设计题与判定题是值得的; 对机械的迁移与逐站模拟, 换模型帮助不大.

## 5 是否换 Fable 5.2 重开: 逐项评估

### 5.1 选的标准

(1) 停点没有路线级的编译否定; (2) 一条陈述挂着多路, 或它就在当前主线上; (3) 能写成 "证明或给出编译反例" 的判定题, 有止损; (4) 文件与别的路不相交.

### 5.2 建议重开的六项

| 序 | 任务 | 对应的软停点 | 交付 (闭项或构造, 加值或否定) | 止损 | 备注 |

**"重开" 一词的口径 (2026-11-10 晚更正).** 六项的性质并不相同, 上表的标题说得太宽:

| 项 | 性质 |
|---|---|
