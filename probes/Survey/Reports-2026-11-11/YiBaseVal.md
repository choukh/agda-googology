#### 1 为什么要做

作者 2026-11-11 定: 第 4 步 (层号不可数) 的验收改成以值下界为主; "闭项合法" 与 "派发完全" 都不携带强度信息. 现在手里有四个高于 `T₃ᵐ` 的合法闭项 (`T⁺ᵈ`, `Tᶜ`, `Tᴾ`, `T⁺`), 读法都没有定. 要知道: 它们各自至少多高, 至多多高, 彼此谁高谁低; 截断 (`Tᶜ` 的链在坐标的极限处截成零) 掉不掉值. 这些是下一步选设计的依据. 中间站给界即可, 不要求同值.

#### 2 目标, 分项; 每项先交再往下. 每一条要么是编译定理, 要么归约成带确切类型的前提

1. **固定对角进仓库.** 在你自己的文件里重写 `feed`, `T⁺ᵈ`, `T⁺ᵈ₂` 与合法性 (这一个文件不要导入带记号闭包的模块, 用 `python3 probes/Survey/scripts/importclosure.py OCF.Align.<模块>` 检查).
2. **固定对角的下界.**
   - 它自己层号上的参照: `L.ψ⁰ (L.Ω (L.suc (toIL (read0 T₃ᵐ) …))) ≼ read T⁺ᵈ` (由 `lower-any` 或 `lower-toIL`; 要 `Zs`, 看 `T₃ᵐ` 读成的层号是否满足).
   - `read T₃ᵐ ≼ read T⁺ᵈ`, 以及能否严格 (`L.suc (read T₃ᵐ) ≼ read T⁺ᵈ` 一类).
   - 与朴素树的关系: `Stage2.NO ≼ read T⁺ᵈ` 是不是定理; 若它要一条层号的值单调性 (与 `MonoT` 同类), 写成带确切类型的前提并条件地证出来, 说明前提在哪些实例上成立. 另一路 (前缀 `YiMono`) 同时在攻 `MonoT`, 不要等它, 不要依赖它的文件.
3. **四个闭项与 `T₃ᵐ` 的比较.** `read T₃ᵐ ≼ read Tᶜ`, `≼ read Tᴾ`, `≼ read T⁺` (第 0 项就是 `T₃ᵐ`, 应当便宜); 各自严格高出多少的下界 (例如不低于 `read T₃ᵐ` 的两倍, 不低于以 `T₃ᵐ` 为坐标的那一步的折叠值, 等等, 看链的第 1, 2 项能给出什么).
4. **四个闭项彼此的比较.** `Tᶜ` 与 `Tᴾ` (截断链与归一链): `read Tᶜ ≼ read Tᴾ` 与反向, 各自是定理, 编译的反例, 还是归约. `T⁺` (主干行) 与 `Tᶜ`, `Tᴾ`. `T⁺ᵈ` 与它们三个. 做得出几条算几条; 每条写明方向.
5. **截断掉不掉值, 最小的见证.** 取一个含极限的坐标 (例如 `YiGenFoldGap` 里的 `wᴾ = lim (1, 1, …)` 的后继), 比较截断行与归一行在这一支上给出的保留结点折到第 0 层后的值: 相等, 截断更低, 还是定不下来. 这是第 4 项里 `Tᶜ` 对 `Tᴾ` 的局部版本, 比整体的比较便宜, 先做它.
6. **上界 (能做多少做多少).** 任何一条 "某个闭项 ≼ 某个有读法的参照" 的定理都算; 做不出就写第一个障碍.

"反例" 要求对象在规范构造的读回域里, 不是退化结点. 有限样本的检查标为测试, 不是证明.

**停下的条件.** 同一处两次重新设计仍过不了检查器; 需要函数外延或 K (可交显式前提的条件定理, 另给不带它的最强结果); 堆到 6G 仍耗尽 (先按手册 §4.2 的对策: 陈述逐字写, 大的参照树放 `opaque`, 隐式参数显式写出, 文件拆小).

不要为了好证而改折叠或闭项的定义: 被量的就是上面列的对象. 发现某个闭项的值低于预想 (例如截断确实掉值, 或主干行的闭项不高于某个低的参照), 那是重要结果, 写成编译过的定理交回.
