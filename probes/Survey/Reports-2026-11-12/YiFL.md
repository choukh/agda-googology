##### 1 判决

**对纲领与目标意味着什么**: F1 的互递归本身不是障碍, 检查器一次就接受. 但折叠能带的不是合法性 `Leg′`, 而是它的可计算部分 (我叫 "树的证据" `E`), 并且带上以后暴露出两个比停机更靠前的问题: 折叠的值随证据的选取而变, 以及保留结点的分支拿不到证据. 第一个问题的修法 (相干的证据) 在第一条保持引理上两种写法都过不了停机检查. 所以 F1 现在只在 "下标的证据由外面给出" 和 "真链第 1 步" 上给出路径, 不足以支持上攻.

- **停机**: 通过. `ψ⊥`, `ψs`, `pres⊥`, `press` 四个函数一个互递归块, 没有改写就过, 冷编译 3 秒, 510 MiB.
- **ω+1 是否有路径**:
  - 有, 条件是下标 ω+1 的证据交到折叠手里. 塔第 1 项对它给的孩子层路线带相邻路径 (`fl-adj`, `refl`), 孩子的底是结点 (`bω-fl`); 给平凡证据时是极限 (`bω-0`). 后两条是有限测试.

- **路线 `Rt′`** 只改 `Ωₗ` 一行: `Rt′ k × ((c : Tr k) → Q k c → Rt′ (h c))`. 写成对 `Q` 参数化的模块 `Rts`, 取 `E` 给折叠, 取 `Leg′` 给第 1 件.
- **链**: 分支连同证据一起迭代 (`Σ (Br ℓ p) (EBr ℓ p)`), 下一个分支的证据是 `press` 对同一次调用的结论. 这是互递归的唯一来源.
- **底带证据**: `Bs ℓ = Σ (Base ℓ) (BE ℓ)`, 目标的底 `T⁺ j = Σ (Tr j) (EN j)`. 链步回灌要输出带证据, 输出带证据要底带证据.
- **检查器逼出的**: 孩子的底及其证据逐处内联 (沿用 `YiLimLegal` 的做法); 不用 `with`, 用 `caseW`, `caseW-ind`, `kp-ind`.
- **读自记号的**: 没有. 新增的都是脚手架 (证据参数), 没有新构造子, 闭包定理没有为它加前提, 值没有提高.

##### 5 第一个障碍

**精确到引理**: 相干证据下的 "加法保持相干"

```agda
+-dn : ∀ {ℓ} (c : Tr ℓ) {x y : Tr ℓ} (d : ℓ ⊢ x ◃ y) (ec : Eᶜ ℓ c) (ey : Eᶜ ℓ y)
     → +-Eᶜ c x ec (dn d ey) ≡ dn (+-mono c d) (+-Eᶜ c y ec ey)
```

它与 `+-Eᶜ` 互递归 (`+-Eᶜ` 的 `lim f` 行要用它造输出的相干). 类型检查都过 (原子情形全是 `refl`), 只有停机不过.

写法一 (直接互递归) 报错原文:

```
CohPlus.agda:16.1-39.98: error: [TerminationIssue]
Termination checking failed for the following functions:
  +-Eᶜ, +A, +-dn
Problematic calls:
  +A a f ea ef A
  +-Eᶜ a (f n) ea
  +-dn a (d n) ea (ef (suc n))
  +-Eᶜ c y ec (dn e ez)
```

写法二 (自然性先对抽象运算在块外证明, 原子情形作前提, 再把 `+-Eᶜ` 传进去) 报错原文:

```
CohPlus2.agda:38.1-52.26: error: [TerminationIssue]
Termination checking failed for the following functions:
  +-Eᶜ, +C
Problematic calls:
  +C a f ea (proj₁ e)
  +-Eᶜ a y ea ey
  +-Eᶜ a x ea
```

- 我对原因的读法 (判断): 相邻序的推导里 `◃t` 的中间树 y 不是 `lim f` 的结构子项, 而 `+-Eᶜ` 在 `lim f` 处要对这些中间树调用自己. 第一种写法里被点名的调用 `+-Eᶜ c y ec (dn e ez)` 就是这一处.
- 按停下的条件 (同一处两次重新设计仍不过) 我在这里停了. 没有编译的否定, 状态是 **未走通**.
- 没有试的两条 (纸面判断): 对 `◃` 的良基证明作递归, 我预计会重新遇到 "值依赖证明的选取"; 另一条见 §7 末.

折叠块本身没有障碍, 没有报错.

##### 7 偏离与事故

- **折叠的参数不是 `Leg′` 而是 `E`**. `Leg′` 只完成了第 1 件 (定义, 闭项满足, 路线可由它算出). 理由是 `no-keep`.
- **`press′` 证的是 "带证据且非零", 不是 "合法"**; ℕ 极限逐项折叠的输出相邻序填 `nothing`. 所以 "折叠保持合法" 与 "闭项合法" 在新折叠上没有.
- **第 3 件的测试**是把孩子层的路线从塔第 1 项取出来再喂给孩子层的折叠; 从塔第 1 项整体出发的那一步是 `tw1-ω+1` (`refl`), 不是一条端到端的形状测试.
- **第 4 件只做了 J2 与闭项带证据**; 单调, `kstep`, `kall`, 接口实填都没有做.
- **`YiFLCheck` 导入了 `YiLimCheck`** 取现成的测试对象 (只读它已有的接口).
- **多交了一个文件 `YiFLCoh`**, 只有相干证据的定义与 `Ωt-Eᶜ`; 失败的两种写法没有进仓库.
- **编译事故**: 没有. 四个主文件都是第一次编译通过. 实验目录里三次失败 (两次停机, 一次是写法二的中间版本类型不合, 改后才到停机报错).
- 没有改已有文件, 没有提交, 只删过自己五个模块的接口.

**供台账的一条纸面想法 (未编)**: "折叠对底是膨胀的" (`β ⊴ ψs … β y e`) 看起来可以对树结构递归直接证, 不经推导. 它能给 "后一项是前一项再嵌入一个孩子" 这种形状的 ℕ 极限 (如 `Ωt (lim g)`) 补上输出的相邻序, 可能让真链多保住几步; 但链值被当作树再折叠时仍要一般的单调, 所以我判断它不是完整修法.
