# 纲领第 4 条重新裁决前的盘点（Rule4）

> 只盘点、给意见，不改 `AGENTS.md`，不替作者裁决。档位：**编译定理**＝本轮在 `<仓库>` 根目录以 6G 堆编译、退出码已核（用共享接口，没有 `--ignore-interfaces`）；**据记录**＝文件头、README、记忆或留档里的话，本轮未核；**判断**＝纸面意见。强度写 ψ₀(Ω_x)，EBO = ψ₀(Λ)。

## 0 一句话结论与推荐（判断）

**丙所要的东西仓库里已经编译完成，一直做到 EBO。** `EboLean3` 不带前提地证明了一切 EBO 标准形的良基 `wf`，此外有基本列封闭、抽出的布劳威尔树 `EBO-tree″` 和 `fgh-EBO″`，本轮退出码都是 0。主审记忆里"记号侧层 3（Acc/良基性）未做"已经过时：11-05 就做完了。所以：

- **丙**：只剩工程缺口，即纲领 1 的 View 实例和成品入口。
- **甲**：碰不到瓶颈。主线缺的是值，不是证书，而第 4 层本来就可以读记号。
- **乙**：强形式（下标是记号项，或照抄 `Syn` 再证一遍良基）就是改了名的丙；弱形式是已封存的带高度一族，在 ψ₀(Ω_{Ω·ω·2}) 被编译否定挡住。

**推荐丁**：EBO 这一档按丙发布；记号无关这一档按已证下界 ψ₀(Ω_Ω+ψ₁(Ω_ω)+ω) 发布，读法 ψ₀(Λ) 只作读法。主线的攀爬停止，或改为有额度的研究。如果作者只要一档成品，就选丙。

依据要点（判断）：主线卡住的那一格，难处在于"Ω 结点的孩子是裸树，比较它们会落进 `obs→dec` 一族和壁垒"，并不在于"不许引用记号"。受记号启发的规则形状，按现行 AGENTS 本来就允许。只有把下标换成记号项，那一格才会消失，而这样做就是丙。

## 1 各种裁决

### 甲：放宽证书（树、折叠、FGH 仍不引用记号，证书可带标签）

**现状**

- 主线终点无条件的值：`YiFYRef.target-low : (h : E.HC target) → RT.Rt h ≼ K.readRW MT.EBOᶻ`，其中 target 是 ψ₀(Ω_Ω+ψ₁(Ω_ω)+ω)（编译定理，退出 0；是序数值下界，参照是记号抽取的树）。
- 历史上走过带标签证书的路线：
  - `ScafLadderQTop` 的 `Tω-label` 到 ψ₀(Ω_{Ω·ω})，`TΩᵠ-label` 到 ψ₀(Ω_{Ω·(m+1)+θ})。编译定理，退出 0；属基本列验收档，闭包不干净。
  - `GoodL` 的 `T2-label` 到 ψ₀(Ω_Ω·2)，用 `Goodᴸ` 证书（编译定理，退出 0）。
  - 证书记号无关的那棵树也到了同一高度：`OrdLabAccept.mono-main : … → Lab (forceᴺ _ (MM.GᴺTω ev p)) (ψ₀ᵗ (Ωt (ψ¹ ∷ [])))`，即在 `LadderMonoMain` 的证书上带字面标签 ψ₀(Ω_{Ω·ω})。这是编译定理，退出 0；`LadderMonoClosed` 的无参数闭项 `Tω₀` 与 `fgh` 也退出 0。

**缺口**（要到 EBO）

- 瓶颈在值：LowKeep 那一格，即 Ω 形状结点下、目标经过某个孩子的路径时，低于目标的槽位保留不住（据 README 与审核留档）。值验收属于第 4 层，本来就允许读记号。放宽证书改不了折叠在这一格上的行（判断）。
- 如果想让证书"指挥"保留，例如用标签给比较表填条目，会遇到一个问题：表要对 Ω 结点的孩子给条目，而孩子是裸树，没有标签。要让孩子带标签，就得把分支下标换成带标签的树，那已经是乙或丙。先验检查里的 `obs→dec` 一族（`branch→wdec`、`hand→wdec`、`viaE→dec`、`full→dec`）管的正是这一类。这是判断：针对这种设计没有编译否定。
- `YiTBObs.no-total`（退出 0）只否定不带 `Maybe` 的全表：塔第 1 项上 `ωᶜ` 与 `ωᵉ` 的层号之间两个方向都没有字面路径。它与标签无关。
- 性质：未解决的数学，与现在主线的缺口相同。

**代价**：说不准（判断）。若要靠甲走到 EBO，至少是主线现估的量级。主审 GoalOdds 第 37 份估修正架构约一万行、token 在 100M 以上（据记录）。

**对纲领与目标的意思**：第 1 到 3 条不变。失去的是 11-03 确认的"证书记号无关"。"让树自足"不受损，但也不前进。

**风险**：最可能还卡在同一格。证书换了来源，折叠的行没有变。

### 乙：接受记号引导的树（定义按记号规则写，定义模块不导入记号）

先说范围。按现行 AGENTS，"受记号启发的规则形状"本来就允许；不允许进成品的是带标签证书的结果（`Goodᴸ`）和抄自记号结构的文法（`Syn`）。乙比甲多放开的就是这两样。

**现状**

- 带高度一族（封存但承重）：
  - 字面 `Lab` 最高到 ψ₀(Ω_{Ω·ω+Ω·n+θ})，对一切 n、θ（`OrdLabAccept` 的 `label-∞`、`label-top` 等，贴在主线 `LadderInfMain` 的证书上；编译定理，退出 0）。
  - 在 ψ₀(Ω_{Ω·ω·2}) 有编译否定：`OrdLabReadTop.no-lab-M₂ : … → Lab (forceᴺ _ (G₂.GᴺTᵠ end zero ev z)) tω·2 → ⊥`，还有 `no-lab-ω²`（退出 0）。现有定义的链行第 0 项与记号的基本列不同；定义不能为验收而改，所以字面标签停在这里。
  - 替代读法 `label-Tᴸ`、`same-M₂` 属前驱结构验收档（退出 0）。
- 序数值验收档的最高处是 `EmbVVInstO2.vv-ω²`，ψ₀(Ω_{Ω·ω²})。**本轮 6G 堆耗尽，退出 251**，所以只能算据记录：手册与 README 记它要较大的堆，主审曾复核。
- 规模（据记录，未重算）：LadderOrd 一族四层 ≈300 / 1090 / 7320 / 21490，到 ψ₀(Ω_{Ω·ω·2})；加上值验收到 ψ₀(Ω_{Ω·ω²}) 约 29580。堆：LadderOrd 主体 >14G（45G 通过），CrossM 25G（手册 §4.2）。
- `Syn`：`Uniform5Assess` 的结论是"全语法加标准形 `Acc`, 进不了成品"，`¬Acc-T` 说不带标准形的语法序不良基（据 RESULTS，未核）。
- `AccTreeLab.Lab≅tree : Lab X t → (h : Acc t) → X ≅ tree t h`（编译定理，退出 0）：带字面标签的树与记号抽取的树互模拟。所以乙的终点若用 `Lab` 验收，树就是丙的树。

**缺口**

- 弱形式，即沿封存一族往上走。从 ψ₀(Ω_{Ω·ω²}) 到 ψ₀(Λ) 还要经过 Ω_{Ω^ω}、Ω_{ε_{Ω+1}}、Ω_{Ω₂}、Ω_{Ω_Ω} 等，历史上每一站都要新的脚手架（翻译蠕变；`T⊤`、ω^ω、ε₀ 未走通，据 RESULTS）。ψ₀(Ω_{Ω·ω·2}) 的字面标签在现定义上为假，乙允许改定义，但新定义要重新设计。这是未解决的数学加大工程。另外，该族的层号是固定码下的位置（`HB`），比较可判定。一旦层号要取回灌的输出（Ω_{Ω₂} 以上），是否会遇到与主线同一格的困难，未知：该族没有到过那里。
- 强形式：层号或分支下标直接取记号项（比较可判定，壁垒不适用），或者把记号文法抄成 `Syn` 再抄一遍 `EboLean3` 的良基。这就是丙换了模块名（判断）。"定义模块不导入记号模块"只关乎导入闭包；AGENTS 已写明导入闭包"只保证不引用, 不说明定义没有受记号启发"。

**代价**（判断）：弱形式要数万行，token 在 100M 以上，依据是封存一族到 ψ₀(Ω_{Ω·ω²}) 已用约三万行。强形式约等于丙，再加改名。

**对纲领与目标的意思**：第 1 到 3 条可以满足；强形式下壁垒不适用，见丙。失去的是"下一步的定义不看记号就能写出"。弱形式里折叠仍是树上的操作，但规则形状是翻译。

**风险**：弱形式卡在高站的字面标签（已有编译否定）和每站的脚手架上，另有堆墙（本轮 `EmbVVInstO2` 在 6G 退出 251）。强形式的风险同丙。

### 丙：机械抽取（记号项沿基本列展开成布劳威尔树，停机由构造性 `Acc` 保证，FGH 在树上算）

**现状**（下列模块本轮都编译过，6G，退出 0）

- 定义：`EboLeanDef` 给出 `T`、`EBOψ`、`HC`、`fgh`；项、序、比较、共尾度、Ω-基本列与 γ-链取自 `EBO`。
- 良基：`EboLean3Omega.wf : ∀ {t} → NF t → Acc′ t`，覆盖一切 EBO 标准形（不限可数），无前提，方法是 Setzer 突出集方法的 EBO 专门版。`Acc′` 是限于标准形的可及性：`acc : (∀ {b} → NF b → b <ᵀ t → Acc′ b) → Acc′ t`。
- 基本列封闭：`EboLeanClosure` 的 `cl-fsn-NF`、`trian-fsn`、`Ctbl-fsn`、`Ctbl-cof`（经 `EboLean3Tree` 编译）。
- 树与 FGH：
  - `EboLean3Tree.hc : NF t → Ctbl t → HC t`；
  - `EBO-tree″ = lim (λ k → tree (hc-tower k))`；
  - `fgh-EBO″ : ∀ n → FGH EBO-tree″ n ≡ fgh (EBOψ n) (hc-tower n) n`。
  - 树类型 `Ord` 只有 zero、suc、lim，与 `src` 里 BTBO 的 `Ord₀` 同形；极限不带单调条件。
- 标签与旧路线：`EboLean3Lab.lab-NF″`；`EboLean3Cmp.fgh≡` 与旧 τ 路线逐点相同。
- 变体：`DirectedViewDirectClosed` 不经 `HC` 中间树，直接用 `wf` 生成树，有 `full-EBO`（与参照双向 `≤ᵛ`）和 `fgh-reference`。
- 记号侧的单调与共尾（`YiCFMono`）：
  - `mono<ⁿ`：对一切可数标准形，s <ᵀ t 推出 `suc (Rt h) ≼ Rt h′`；
  - 另有 `below-rowⁿ`、`cofinNF`，后者来自 `YiCFCofin.cofin`。
  - 这些说明抽出的树尊重记号的序。
- 导入闭包：`EboLean3Tree` 共 25 个模块，本地 14 个，全在 `probes/OCF/Align`，包含 `OCF.Align.EBO`（丙本来如此），不含 `archive`。14 个本地文件都是 `--safe --without-K --lossy-unification`；文本检索没有 postulate、停机或正性编译指示、`trustMe`、funext。
- 早先的事实：`AccTree.acc→nat` 与 `¬EBO-number`（经 `AccTreeLab` 编译）说明，`EBO` 文件字面的 `Acc`（在全体项上）只在自然数上成立。所以需要的是限于标准形的 `Acc′`，而它已经有了。`archive` 里 Setzer OT_I 的 `wellfounded`（τ 路线，约 5486 行）已被 `EboLean3` 取代（据记录，未编译）。
- 行数（据记录，未重算）：120 / 131 / **1513**，加标签 1533；其中良基部分 487 行。`DirectedView` 变体的执行切片是 1420，口径不同。
- 与标准 EBO 的对应：我方 EBO 与 koteitan `ExBuchholz` 的项、序、基本列"看来逐项相同"，依据是测试和逐分支阅读，未形式证明。`ExBuchholz` 的序型等于 ψ₀(Λ) 是 Lean 里经典的已构建结果（据 OrdinalNotationsGuide §5，未读源码）。仓库内"值是 EBO"是定义：参照树就是它自己。

   - 可数项：`cof` 给出 c0、c1、cω 三种情形，树也按它定义，所以实例是例行工程（Ω 种类 `Kd` 取空）。
   - Ω-共尾项（Ω_ν、ψ_ν(…) 等）：在丙里只是语法，没有树值。
     - 若纲领 1 也要它们有 View，Ω 分支只能按记号项下标，而不是"低层合法树"。
