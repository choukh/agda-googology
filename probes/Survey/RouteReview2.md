## 0 结论

**对问题 1 (是否在正确的路上): 是, 在纲领层面; 但到终点 EBO 的路上有一个结构缺口与一个汇聚的单点, 两者任一不解, 主线按现在的形状到不了终点.** 信心: 纲领合规是高 (有编译器与脚本保证); "主线能到 EBO" 是中低 (判断, 依据见风险 1, 2).

分三层说:

1. **纲领 (不可违背) 四条, 主线都守住了, 而且是机器保证的.** 树在先 (`A`, `H`, `D₊` 都是归纳类型, 大数是 `FGH (ord …)`); 无公理 (`--safe --without-K`, 无公设、无洞, 本次抽查四个文件属实); 壁垒 (比较只在世界 `W` 之内, `cmpH` 要字面公共上界 `Λ`, `no-glob`/`no-world-top` 是定理; "此设计不推出 LPO" 没有也不可能有定理, 这是合读, `HtFeed` 入口已如实写); 记号无关 (主线定义的导入闭包干净, 本次复核 `HtOutFeed`, `HtCrossInst`, `EndLowH`, `KValTree` 属实; 验收文件单列). 这一层没有问题.
2. **目标 ("让树自足") 有实质进展, 但只在合法性与形状上, 没有在值上.** 三条进展判据: 闭包定理与阶段无关 — `HtFeedGrow.Sup` 对一切 `Λ` 与节点族一条 (定理), `Lg-sum`, `Lg-rd` 无前提 (定理), 这是真的; 下一步不看记号就能写 — `HtOut.Fb` 从 0 出发只用回灌与 ℕ-对角生成高度 (定义, 切片不到达 `HtFeedHt`), 这是真的; 树侧合法性标准 — `LgH`, `Cont` 两条字段由 `drop-lim`, `drop-suc`, `no-weak` 逼出 (定理), 这是真的. **缺的是树侧的值判据**: 一切 "多大" 的陈述, 要么是与记号参照树的 `≼` (只到 ψ₀(Ω_Ω), `T₀≈`, `T≈`, 定理), 要么是一步严格增长 (`step-T₁`, `hs-strict`, 定理), 要么是纸面读法. 高度树一族 (`HtFeed`, `HtOut`, 现在的主线闭项) **没有一站**有序数值定理, 连粗界也没有 (`EndLowAccept` §4 把它写成模块参数 `Acc₁`, 本次读过). 所以 "树自足" 目前是 "树会写合法的定义, 还不会判断定义有多大".
3. **到 EBO 的路径上, 两件事决定成败, 都已经在代码里显形了, 但地图还没把它们标成关键路径:**
   - **结构缺口 (定理 + 判断):** `H` 是第二数类的树, `EndLowH.no-top` (定理, 本次复核) 说没有高于一切高度的 `Λ`; `EndLowAccept` §5 (判断) 说终点下界从第 3 级 ψ₀(Ω_{Ω_Ω}) 起要 `Λ ≥ Ω_Ω`, `H` 里没有. EBO = ψ₀(Λ), Λ 是 Ω-塔的极限, 要 ω 个数类的高度. 现在主线的类型上限是 ψ₀(Ω_x), x < Ω₂ (读法), 距终点差整个塔.
   - **汇聚的单点 (定理 + 判断):** 五条线卡在同一条引理上: 折叠对状态、上下文、输入世界、高层输入值单调 (`HtCrossInst.MonoStep`/`MonoL`; `CvLayer` 停下的地方; `DVal` 的 nκ 对齐; `EndLowAccept.ToLimit` 的前提 `mono`; ψ₀(Ω_{Ω+1}) 上界). 它未证, 也未被否定. 历史上同类的值猜想**多数被编译过的反例推翻** (`¬Bis-mono`, `¬mono-on-Mono`, `¬toB-mono-κ`, `¬assoc`, `¬κ-refl`, `no-round`, `ψᴱ-not-mono`), 所以 `MonoStep` 为真不是默认.

## 1 风险 (按严重度排序)

每条写: 内容; 证据与档; 后果.

### R1. 高度类型 `H` 到不了 EBO 需要的高度 (结构)

- **证据.** `EndLowH.no-top : ¬ Σ H (λ Λ → ∀ h → hs h ≤ᴴ Λ)` (定理, 本次复核). `EndLowAccept` §5: 第 3 级 `treeE 3` 读 ψ₀(Ω_{Ω_Ω}), `Climb.step` 在 k+K=2 处是第一个缺口 (判断, 文件自述只有 `no-top` 一环是定理). `HtOut` 入口第一个障碍 4: "x_ω 之上要第 2 层的输出作高度, 要第三数类的高度树" (判断).
- **后果.** 主线现在的闭项 (`T-fbω` 等) 不论值多大, 按类型就在 ψ₀(Ω_{Ω₂}) 以下 (读法); 终点下界证明不可能在当前 `H` 上完成. 要改 `H` 的类型 (作者已定 "先不改 H", 并派 HtTower). **风险在于怎么改**: 若写成 `H₁`, `H₂`, … 逐数类加 (HtTower 的 "高度的高度"), 就是 "每升一级加一维" 在高一层重现 (README 翻译账里 `SumClimb` 被判 "加深" 的同一模式), 而且 Ω-塔的极限 Λ 要对角过一切数类, 比较两个不同数类的高度正是壁垒最近的地方. 封存路线 5 (`LevelFix.LF`, 一个归纳-递归类型含一切层号到 Λ) 已经做过 "一次封闭全部数类" 的类型, 第一个障碍在 ψ₀(Ω_Ω) 的证书, `RouteSeal` §5 自己写了 "差树的合法性由形状给出可能正好补上这一步". HtTower 若不先读它, 大概率重做一遍.
- **档.** `no-top` 定理; 其余判断.

### R2. 一切值的结果汇聚于一条未证的单调引理, 而它可能是假的

- **证据.** `HtCrossInst.MonoStep = sum one (Q.yc Q.ΔΩ (Q.τ₀ tt)) ≤ sum b₀ X′` (本次读过): 同一实例里, 空状态折叠 Ω_Λ 不高于链第 0 项的状态里折叠. `hs-reduce<`, `hl-reduce<` 条件于它 (定理, 条件). `EndLowAccept.ToLimit` 条件于 `MonoL` (本次读过). `CvLayer`, `DVal` 入口第 5 条, `HtCross` 第一个障碍 1, `L1Val` 第 3 条都指向 "折叠对高层输入值单调 + 对世界单调". ψ₀(Ω_{Ω+1}) 上界从 `SumOne` (11-04) 起就卡在这里, `RouteSeal` §4 记 "跨树互模拟估计 1200 到 2000 行, 这个估计出现过三次都没写过".
- **反面的先例 (定理).** `L1ValShape.¬Bis-mono`, `L1ValSup.¬mono-on-Mono`, `L1ValKappa.¬toB-mono-κ`, `DValNeg.¬assoc`, `DValNeg.¬κ-refl` (本次复核 `DValNeg`), `LayerTrNeg.no-round`, `Cumsum.ψᴱ-not-mono`: 都是 "折叠对某个自然的值序单调" 被真实折叠上的具体反例推翻. `MonoStep` 比它们更强 (要同时对状态、上下文、世界单调), 没有理由默认为真.
- **后果.** 若假: 高度树一族的 "增长" 只剩 `Sup` 一档 (不塌缩), 跨高度比较与终点下界都要换形状; KVal, EndLow, HtCross 三条并行线同时失效. 若真但证明是 5000 行量级: 第 4 层的成本把 "树侧行数小于记号侧" 的标杆直接冲掉 (对照 `LadderOrd` 层 4 约 21490 行, README 行数口径).
- **档.** 引理未证; 先例是定理; 后果是判断.

### R3. 序数值验收不验大数; 终点 "互相 ≼" 对成品的数没有约束

- **证据 (定理, 本次新写).** `Review2Blind.blindᴬ`: 两个字面合法 (`Lg`) 的 `A`, 在主线验收用的 `TLRuleSpec._≤_` 下互相 ≤, `FGH (ord ·) 2` 一个 8 一个 2048. 同 `OCFSpecNeg.spec-blind` 在 `Ordᶜ` 上的结论, 这里落到主线自己的类型与序上. `AGENTS.md` 已承认 "这两档的序数值是定理, 基本列不一致, FGH 的值可能不同".
- **后果.** 终点若只证 `EBO-tree ≼ ⟪T⟫` (作者 11-05 定的终点验收), 得到的陈述是 "成品的序数不低于 EBO", 不是 "成品算出 EBO 的大数"; 成品的大数由主线自己的基本列决定, 它与记号的基本列已知错位 (`same-M₂` + `no-lab-M₂`, 定理; `SumOneAccept.gap₀` 第 0 项错一位, 定理). 这在纲领内是允许的 (纲领 1 说大数是树上 FGH 的值), 但对外表述要分开 "序数 ≥ EBO" 与 "等于 EBO 的 FGH". 此外下界 `EBO-tree ≼ ⟪T⟫` 推不出 FGH 逐点 ≥ (`≼` 不保 FGH 单调, 见 `Review2Blind`: ω ≤ ω⁺ 且 ω⁺ ≤ ω, FGH 却一边大一边小), 所以 "成品的大数不小于 EBO 的大数" 也不是下界定理的推论.
- **档.** 定理 (本次) + 判断.

### R4. `Funext` 作前提的 "定理" 不能进成品, 而跨高度的全部正面结果都带它

- **证据.** `HtCrossSim.Funext : ∀ {A B} {f g} → (∀ x → f x ≡ g x) → f ≡ g` (本次读过, `Set₁`), 是定义出的命题, 不是公设 (合规); `inst0`, `change`, `lg-irr`, `hs-reduce`, `hl-reduce`, `hz≤1`, `path-rel` 都以它为参数 (定理表自述); `EndLowAccept.ToLimit` 也要 `fe : Funext`. `HtCross` 入口已注 "成品若要无条件, 要把第 0 层的相等换成值上的 ≈ (判断)".
- **后果.** 纲领 2 (无公理) 与 "强度是定理有三档" 之下, 带 `Funext` 的结果只能算 "条件定理", 不能作终点验收的证据; 也不能进 "证书". 现在它被写进状态表的 "定理 (多数以 Funext 为前提)" 一行, 读者容易当成无条件. 若等到终点再换成 `≈ᵛ`, `HtCrossRun` 的十六个函数要重写一遍.
- **档.** 定理 (条件) + 判断.

### R5. "读法" 积累成一条很长的无定理链, 且中间站连粗界都没有

- **证据.** 高度树一族的读法表: `T-Ω` … `T-ΩΩω`, `T-fb n`, `T-fbω` (ψ₀(Ω_{x_ω}), x_{n+1}=ψ₁(Ω_{x_n})), 入口自述 "这一节没有任何一条是定理". 有限测试的分辨力: `HtOutTest` 对照行说比较器 "深度 12 分不开 Ω² 与 Ω³", 所以测试对值无分辨力 (文件自述). 作者 11-05 定 "中间站给界"; 但目前 ψ₀(Ω_{Ω+1}) 以上**没有任何一站有上界或非平凡下界** (`EndLowAccept` §4 把 `Acc₁ : BTBOᴵ ≼ ⟪T-fb 1⟫` 写成参数, 即连 "第 1 站不低于 ψ₀(Ω_Ω)" 都没做).
- **后果.** 读法链一旦某一环错 (如 `toD` 在极限坐标处不忠实, `HtOut` 自述), 上面的站名全要改, 而且不会被任何编译告警. 地图的 "现状" 表用 ψ₀(Ω_x) 命名这些站, 外人会当作强度.
- **档.** 判断; 分辨力不足是测试档的自述.

### R6. 行数标杆比的是两种不同的保证

- **证据.** 记号侧 "第 3 层" = 良基 (`wfNF`, `cl-fsn`, 带标签的树与 FGH, 定理); 树侧 "第 3 层" = 合法性由形状给出 (`Lg-TΛ`, `Lg-T-fbω`, 定理). 前者保证 "这个项的序数是它说的那个, FGH 可算"; 后者只保证 "树是合法的布劳威尔树, FGH 可算", 对序数一个字不说 (`CumHt.HS-Nxˢ`: 不读输出的链也 `HS`, README 自述 "`HS` 不是强度证据"; 同理 `Lg`). 树侧要达到记号侧第 3 层的保证, 是第 4 层 (值), 而那一层在 `LadderOrd` 上是 21490 行 (README 口径), 在差树上未走通.
- **后果.** "树侧到第 3 层行数小于 EboLean" 几乎必然成立 (HtOut 层 3 为 649 行), 但它不说明树侧更经济, 只说明树侧少做了一层. 标杆若被当成路线优劣的证据, 会误导.
- **档.** 判断, 依据是两边各自的定理陈述.

### R7. 工程: 文件与并行线的规模已经超过复核能力

- **证据.** `probes/OCF/Align/` 1260 个文件; 现状表 70 余行; 封存族里 `LadderOrd` 要 45G、14 分钟, `CrossM` 25G, `WorldTH` 15 分钟; 每次审核 "删接口文件后重新编译" 只做入口. 五条线并行 (KVal, EndLow, HtTower, HtTotal, EboLean), 其中三条 (KVal, EndLow, HtTower) 的成败取决于 R2 或 R1 同一件事.
- **后果.** 同一引理在三条线各估一次、各写一遍脚手架 (`DVal` 1028 行, `KVal` 另起, `HtCross` 641 行), 都在等 `MonoStep`; 封存族 "保持可编译" 的义务没有人跑. 旧结论失效时 (如 R1 要改 `H`) 不知道哪些文件受影响.
- **档.** 判断; 规模是事实.

### R8. 验收参照树的构建链条脆弱

- **证据.** `EBO-tree` 经 `WfTauNF` 导入归档 `archive/src/Mahlo` (43 个文件, 需另加 `--hidden-argument-puns -W noUnsupportedIndexedMatch` 的库文件, 每次拷副本; `NotationWF` §1, 作者 11-04 定不拷进 probes). `AccTreeLab.Lab≅tree` 需 `Acc t` 前提 (上次审查已注).
- **后果.** 不是数学风险 (定理无前提), 是复现风险: 归档一动或 Agda 升级, 终点验收编译不过; 外人无法按 README 一条命令复现 `fgh-EBO`.
- **档.** 事实 + 判断.

### R9 (低). `S = ω⋅` 与 "ψ(0)=Ω_τ" 两处约定, 只在 ψ₀(Ω_Ω) 验过

- **证据.** `TLRule.ω-uniq`, `blind`, `gap-Ω₁`, `AddClo.no-clo-·2`, `TD≺` (定理): 一步 S 是约定, 加法封闭后唯一; 地板是值逼的. 折叠对 S 参数化 (`HtFeedFold` 的模块参数, 本次读过), 高处用的是同一个 `ω⋅`.
- **后果.** 若高处某站需要不同的步 (判断: Buchholz 的 ψ(a+1)=ψ(a)·ω 对一切 a, 大概不需要), 现在没法发现, 因为高处没有验收. 列为低.

## 2 预防措施 (按优先级, 每条对应风险)

### P1 (R2, 最先做, 一两天): 先试否定 `MonoStep`, 再决定证它

- 在最小实例 `Λ = hs hz` (ψ₀(Ω_{Ω+1})) 上, 用已有的 `same`/比较器与 `CvFoldInst.Kn` 一类的具体输入, **有限测试** `MonoStep` 两边的前几项; 同时按 `L1Val` 的反例模式 (质量放在不同世界) 构造 `Chn` 重折叠的反例候选. 若找到反例, 写成编译过的否定, 三条并行线立刻换形状, 省下的远多于两天. 若没找到, 把 `MonoStep` 拆成两条可独立证伪的子引理 (对状态单调; 对世界单调), 各自在 Λ = hs hz 上先证, 不先在一般 Λ 上写.
- 停做: 在 `MonoStep` 定下来之前, 不再在 KVal、HtCross、EndLow 三处各自铺脚手架等它; 三条线合为一条, 目标只写一个: "`MonoStep (hs hz)` 的真假".

### P2 (R1, 开 HtTower 之前): 先定高度类型的终局形状, 写否定定理划边界

- HtTower 动手前先读 `RouteSeal` §5 (`LevelFix.LF`) 与 `LevelFixNeg` 的两条否定, 回答 "逐数类加 (`H₁`, `H₂`, …) 与一次封闭 (`LF` 式) 哪一个能装下 Ω-塔的极限 Λ 而不触壁垒". 要的编译结果 (在 R1 的意义上是 "摆脱侧先手"): (a) 一条否定定理, 形状如 `no-top` 推广: 任何 "分支定义域是前一数类" 的分层高度族, 其对角 (Λ) 在哪个世界里可比; (b) 或一个正面定义: 只用一个归纳类型 (世界是前一数类的元素) 装全部数类, 并证 `LgH` 的闭包仍是一步定理. 判据: 每升一个数类不改折叠 (`HtFeedFold` 以 `Λ : H` 为参数, 若 `H` 变成族 `H n`, 折叠不能按 n 重写). 若做不到 (a) 或 (b), HtTower 就是 `SumClimb` 在高一层的重演, 翻译账应记 "加深".

## 4.1 对 `AGENTS.md` 纲领 1 的新解释 (作者 2026-11-05, 中间层须有布劳威尔树的 View)

本报告写到一半时 `AGENTS.md` 加了这条解释: 中间层可以比布劳威尔树多 (差、坐标、世界), 不能少; 每个对象要能看成零、后继、ℕ-极限 (严格递增) 或 Ω-极限 (按低层合法树分支), 各部分仍是同类型对象, 且值与构造子作用在各部分上互相 `≼`. 看法 (判断):

- 这是迄今最接近 "树侧值判据" 的一条标准, 也正好对准 R2 的位置: View 的 "值上一致" 要一个中间层上的值关系, 对 `ni` 已有 (`DVal._⊑ᵈ_`, 逐分支, 坐标按值对齐), 对 `nκ` 没有 (`DVal` 入口第 5 条; `¬κ-refl` 说无条件自比不行). 所以这条标准在第 1 层以上目前**不满足**, 满足它与证 `MonoStep` 是同一件事, 不是两件.
- 已有的部分结果可以直接按这条标准重读: `LayerTr.toB`, `Lg-toB` (第 1 层差树读成合法布劳威尔树, 定理) 是 View 的 "形状" 一半; `no-round` (定理) 说值上不互逆, 加 `Cv` 才成立 (`round-Cv`), 所以 View 的 "值一致" 一半只在 `Cv` 下成立; `BrwHigh.incr-blind` (定理) 说 View 反过来读不回增量, 这与 "可以比布劳威尔树多" 一致, 不是障碍. 高度树 `H` 本身就是布劳威尔树 (View 是恒等), 但 `hΩ g` 的分支取遍 `A` 含不合法坐标, 与解释里 "按低层合法树分支" 不完全同形 (`EndLowH` 的 `≤ᴴ` 也取遍 `A`); 这一点要么改 `H` 的分支定义域 (`HtOut` 障碍 2 的出路之一), 要么在 View 里只看合法坐标, 应早定.
- **P9 (对应这条解释):** 把 View 写成一个对中间层类型的记录 (零/后继/ℕ-极限/Ω-极限四条读法 + 四条值一致), 先在第 0 层 (`sum`/`dif`, 已有 `round₁`, `round₂`) 与 `H` 上实例化为无条件定理, 第 1 层的 `ni` 段条件于 `Cv`/`HA₁` 实例化, `nκ` 段写成参数. 这样 R2 的那条引理就有了一个由纲领给出的、不读记号的目标形状, 也让 KVal 的关系直接对准它而不是另起一套.
