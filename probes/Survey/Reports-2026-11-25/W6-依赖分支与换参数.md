#### 2. 设计 (阶段一、二)

**W6Block**
- Sg 加字段 `Dg : Set`, 取值 `DG (nd (sΩ k) h) = ⊤`, 其余为 ⊥。
- 新构造子:
  `dg : T S → (Y : (c : C S) → D S c) → ((c : C S) → R S c (z₀ S c) (Y c)) → Dg S → T S`
- 序只加一条: `◃d : ∀ {x Y e δ} → Lt S x (dg x Y e δ)`。
- 读回: `↑ (nd (sΩ k) h) (dg x Y _ _) = nd (sΩ k) λ c → ↑ (nd (sΩ k) h) x ⊕ ↑ (h c) (Y c)`。
- `Eh`、`Emh`、`EP` 补上与 `Ω top (λ d → up x d (Y d) (e d))` 同语义的行。

**W6Ops**
- `+`、`+-mono`、`zl` 补 dg 行; `ι` 在第 0 层上, dg 不可居, 由检查器自动判空。
- `Ωt (nd (sΩ k) h) = dg zero (λ c → proj₁ (Ωt (h c))) (λ c → proj₂ (Ωt (h c))) tt , ◃d`

**W6Path**
- `OkS (sΩ k) h = Ok k × ((c : Tr k) → (k ≤ h c) × Maybe (h zero ≤ h c)) × Maybe ((c d : Tr k) → h c ≤ h (c + d))`
- 补了 `↑⊑+` 的 dg 行, 定义 `hN`、`tw-mono` (证法同 R15Mono)。
- `Ok-tw (suc n)` 给 `just (tw-mono n)`; `OkS⊕` (读回层号) 给 `nothing`。
- `◃→⊑` 与 `OkO↑` 补 dg 行。

**W6Loc:** 只改模块名与导入。

**W6Fold**
- 迭代子 `E / Einf / Emono / It / Itinf / Itmono` 补 dg 行, 语义是 Ω top 行复合 up 行。
- ψ 的 dg 行 (完整代码在 W6Fold 第 402–411 行):
  - 目标经 `ink` 或 `inu`: 与 "Ω top 行复合 up 行" 作用在去糖形式上逐字相同。

  - 如果只传 k 和 h, 检查器看不出 `h c` 小于 `nd (sΩ k) h`, 与 sL 行里树不变小、层号变小的 emb 调用复合后停机检查失败。这一点实测过。

#### 3. 编译定理 (陈述逐字)

##### W6Shape
```

**steer-node** (编译定理, refl)。白话: 在原层号 N 上, 规范 Ω 树朝孩子 c′ 里的层 j 折, 结果是 node⁺; 判定是原层号的 kp; 第 d 支逐字是孩子 c′ + d 里沿字面路径的折叠。
```

    → ψ N oN S j (inc c′ v) β (proj₁ (Ωt N))
    ≡ node⁺ (kp N oN top (inc c′ v))
        (λ d → ψ (hN n (c′ + d)) (proj₂ oN (c′ + d)) (λ i u → S i (inc (c′ + d) u)) j (v ∙ tw-mono n c′ d) β (proj₁ (Ωt (hN n (c′ + d)))))
        (λ d → proj₁ (ψ (hN n (c′ + d)) (proj₂ oN (c′ + d)) (λ i u → S i (inc (c′ + d) u)) (tw n)
                        (self ∙ lift (tw n) (↑ (tw n) (c′ + d))) (S (tw n) (ink self)) (proj₁ (Ωt (hN n (c′ + d))))))
```

**steer-left** (编译定理, refl)。白话: 树是 "x 右边接上规范 Ω 树" 时同样成立, 底换成 x 的折叠。
```
  steer-left : (S : Base N) {j : L} (v : j ≤ hN n c′) (β : Tr⁺ j) (x : Tr N)
    → ψ N oN S j (inc c′ v) β (x + proj₁ (Ωt N))
    ≡ node⁺ (kp N oN top (inc c′ v))
        (λ d → ψ (hN n (c′ + d)) (proj₂ oN (c′ + d)) (λ i u → ψ N oN S i (inc (c′ + d) u) (S i (inc (c′ + d) u)) x) j
                 (v ∙ tw-mono n c′ d) (ψ N oN S j (inc c′ v) β x) (proj₁ (Ωt (hN n (c′ + d)))))
        (λ d → proj₁ (ψ (hN n (c′ + d)) (proj₂ oN (c′ + d)) (λ i u → ψ N oN S i (inc (c′ + d) u) (S i (inc (c′ + d) u)) x) (tw n)
                        (self ∙ lift (tw n) (↑ (tw n) (c′ + d))) (ψ N oN S (tw n) (ink self) (S (tw n) (ink self)) x) (proj₁ (Ωt (hN n (c′ + d))))))

**branch-zero** (编译定理): 第 0 支就是孩子 c′ 本身。

#### 5. 开新行前的先验检查三条
1. **目标是指定孩子的, 还是对一切孩子一致的?** 目标在指定孩子 c′ 里; 换参数后, 对一切分支 d 都给出同一个函数 `v ∙ m c′ d`, 是一致的。
2. **孩子下标类型上有没有证据函数?** 有, 就是证书字段 `m : (c d : Tr k) → h c ≤ h (c + d)`。它只在塔上取 `just`。
3. **有没有按存在性保留?** 没有。保留判定沿用原层号上的 `kp … top (inc c′ v)`, 没有新增 "层号字面相等" 或 "槽位存在" 的测试。唯一新增的分派是按证书的 Maybe 字段: 它是层号自带的数据, 不是对树或下标的判定; 写法与 W5 已有的 Maybe 字段同类。

#### 6. 改 Ωt 之后, 可数层号上的折叠行有没有变化 (判断, 依据是逐条对读定义)
没有变化:
- 可数层号上 `DG = ⊥`, dg 不可居。
- 第 0 层、sS、sL 上的 `Ωt` 没有改; 可数层号的子层号仍然可数。
- ψ 在 zero/sS/sL 上的行、`kp`、`Ok` 的 sS/sL 部分, 与 W5 逐行相同。
- `ψUi` 的搬移只影响 Ω 形层号; E 与 It 只加了 dg 行。

W4 和 W6 的树类型不同, 没法写跨模块的编译定理, 所以这里没有编译定理, 也没做有限测试。

#### 7. 没做成的与提醒
- **值没有证。** 换参数的一行只取孩子 c′ + d 这一族分支。它与整个 Ω 分支同值, 依赖于这一族在全体孩子里共尾: 这是判断, 没有证。
- **dg 的序只有 ◃d 一条, 没有 dg 内部的同余规则。** 所以 "沿 dg 内部步进的 ℕ 极限" 写不出来。规范树和现有运行都用不到这种极限, 但它是表达力上的限制。
- **性能:** 对闭项直接写 refl (例如 `B₂ jZ … ≡ ψ (h₂ z₁) …`), 或 `cong` 的隐式参数留作元变量, 都会让检查器把大闭项算开, 退出 251。
  - 解决办法: 先写对变量成立的 refl 引理, 再用逐字相同的项去实例化。
  - 另外 `cong` 的 `{x}{y}` 要显式给出。
  - 如果第一次退出 251 就算失败, 失败的那句首个错误原文是 `agda: Heap exhausted; Current maximum heap size is 6442450944 bytes (6144 MB).`
