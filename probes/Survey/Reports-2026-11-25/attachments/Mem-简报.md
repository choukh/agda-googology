## 一、记忆

记忆系统自己的规则 (整理要符合它):
- 每条记忆一个文件, 一条事实, 带 frontmatter: `name` (短横线连接的 slug), `description` (一行, 用来判断是否相关), `metadata.type` 取 user / feedback / project / reference.
- 正文里用 `[[name]]` 连到别的记忆; 指向还不存在的名字不算错.
- `MEMORY.md` 是每次会话都读入的索引: **每条记忆一行**, 形如 `- [标题](文件.md) — 钩子`, 没有 frontmatter, **不放记忆的内容**.
- 只留会改变今后做法的、跨多次会话有效的东西; 仓库里已有记录的过程不必留在记忆里; 确实错了的记忆要改掉.

要做的:
1. **索引.** 现在有的行长达上千字符, 把内容写进了索引. 把每一行压成一两句钩子 (不超过约 150 个字符): 这条记忆是什么, 什么时候该读它. 缩短之前先核对: 那一行里的内容若在对应文件的正文里没有, 先并进正文再缩短. 每个文件恰好一行. 按类型分成四组 (user, feedback, project, reference), 组内按日期从新到旧.
2. **frontmatter.** 每个文件: `name` 等于文件名去掉扩展名; `description` 只有一行; `metadata.type` 合法. 已有的其它 metadata 字段 (`node_type`, `originSessionId`, `modified`) 原样保留.
3. **取代关系.** 一条记忆被更晚的记忆明确取代或修正时 (正文写明的才算, 如 "作者某日反转了…", "…不再适用"), 在被取代的那条正文开头加一行 "**已被 [[新条的 name]] 取代（日期）**: 一句话说明", 并在索引那一行末尾注明 "(已被取代)". 旧正文不删.
4. **feedback 与 user 两类**: 作者的原话 (引号里的) 与 Why / How to apply 的内容逐字保留. 只允许改格式 (frontmatter, 链接), 不压缩, 不改写.
5. **project 类里写成长流水的几条** (至少 `stage-current`, `research-direction-alternation`, `w4-audit-2026-11-24`): 改写成三部分: 现状 (以文件里日期最新的那一段为准); 仍然有效的教训与 How to apply; 过程去仓库的哪份文件看. 被后文明确撤回或更正的中间说法, 不再留全文, 只留一句 "曾这样判断, 后来被什么推翻". 教训, 作者原话, Why / How to apply 一条不丢. 仓库里已有记录的过程细节用指向代替.
6. 不新增记忆; 不改变任何一条指导的意思; 拿不准是否过时的, 不动, 列进回报.
