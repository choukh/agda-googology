# 第五轮：原始项语法与闭包表达式的无损转换

日期：2026-09-08。

本轮实现 Mahlo 原文的主项序列表示、原始项形成规则的判定，以及到第四轮闭包表达式的可逆嵌入。**已经有 T′ 的语法检查，尚未有 OT 的合法性检查或真实序数比较。**

## 1. 原始项形成与类别

依据 [Setzer Mahlo 论文](https://csetzer.github.io/articles/mahlo.pdf) Definition 3.2（原始 PDF 第 6 页；直接核对页面），[Syntax.agda](Notation/Syntax.agda) 使用相互定义的 `Term` 和 `Principal`：

- `Term` 是主项序列；空序列代表零，单元素序列代表该主项。
- 主项有 φ、ψ、Ω 和 M 四种构造。
- 两项及以上的和只有序列表示，不额外引入二元和构造或带零的包装。

底层数据可表示非法 ψ 指标；谓词 `Raw` 按 T′ 规则排除它们。`raw?` 返回形成证书或反证，`regular?` 判定一个原始项能否作为 ψ 指标。另有完全结构递归的语法相等判定 `term≟`，没有使用序数比较。

I′、R′、Fi′、Car′、G′ 和 Suc′ 的类别标签是结构计算；标签单独为真不代表输入合法，需要同时满足 `Raw`。尤其 **Fi′ 不是 R′ 的同义词**。

这些表示和规则的来源对应经过逐条人工核对；尚未把论文中的自然数编码翻译为 Agda 并证明与之同构。不能把语法对应审阅称为已经完成参考 OT 的形式化同一性证明。

## 2. 无损表达式转换

[SyntaxBridge.agda](Notation/SyntaxBridge.agda) 将主项序列转换为第四轮的 `Expr`，多项和取右结合、没有末尾的 `+ 0`。已证明：

| 结果 | 含义 |
|---|---|
| `roundtrip` | `flatten (encode a) ≡ a`，对所有底层语法成立 |
| `injective` | 不同主项序列不会因编码而合并 |
| `idempotent` | 表达式的序列化规范处理是幂等的 |
| `encoded-canonical` | 编码所得表达式已是这种固定表示 |
| `ClosureOnTerms.seed` | 序列上的种子可进入拉回的计算闭包 |
| `ClosureOnTerms.finite-character` | 序列上的闭包证书可以提取有限的**序列种子列表**、包含证书以及仅靠这些种子仍属于闭包的证书 |

`flatten` 只展开加法表达式的括号并消除空序列。它不排序、不执行序数加法，也不检验正规性。这里“规范处理”仅指数据表示；它不是把任意表达式化为 OT 正规项的算法。

`ClosureOnTerms` 通过已证转换使用现有有限闭包算法；比较函数仍是显式输入。与原文闭包的等价性依然需要 OT 正规分解及其闭包性质。

## 3. OT 正规性仍需哪些条件

直接核对同一论文 Definition 3.6（第 7 页），后续实现必须保留以下额外条件，而不能把 `Raw` 改名为 `Valid`：

| 构造 | 除子项属于 OT 外还需验证 |
|---|---|
| 多主项和 | 主项从左到右不递增 |
| φₐb | b 不属于 Cr′(a)，且排除 b = 0、a 属于 G′ 的情况 |
| ψπb | π 属于 R′，并核对 π、b 的辅助闭包条件 |
| Ωₐ | a 不属于 Fi′，且 a 不是零 |
| 0、M | 基本项 |

ψ 的辅助闭包条件涉及原文 SC、G 和顺序比较；它不是第四轮任意传入一个 `lt` 就自动得到的性质。

例如 Ω₀ 可以通过 `raw?`，却应被未来的 OT 判定拒绝；本轮测试显式保留了这个区别。第四轮 `ClosureChecks` 中的人工布尔表也仍然只是算法夹具。

## 4. 下一项实际证明任务

进入 Definition 3.3 的比较／支撑相互递归：先依据现有语法列出各分支及调用的递减量，接着实现真实比较和 SC、sc、G。需要特别处理 ψ 比较中对支撑集成员的递归调用，以及反向比较兜底分支，证明调用递减，不能通过关闭终止检查实现。

之后实现 Definition 3.6 的 OT 判定，证明正规分解保留合法性，再证明序列上计算闭包与参考闭包对应。自然数编码／解码、生成归纳及宇宙小性编码的连接仍待完成。

本轮没有证明 Lemma 3.4 的线性序、distinguished-set 唯一性、Mahlo 反射、端点、基本列或增长率。量级验收 C1–C7 均未整体验收通过。
